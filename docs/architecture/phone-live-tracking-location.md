# Phone live-tracking location sharing

The phone recording and guidance service owns a fused-location request when either feature needs GPS. It publishes copies of the original Android location callbacks, their source interval, and the active subscription generation in process. The location object retains its original wall-clock time, monotonic time, speed, accuracy, and other provider fields. Stopping or replacing the source invalidates the previous generation; callbacks from an old service instance cannot publish to the new one.

Live tracking uses a recent shared fix only while its source is active, its interval is no slower than live tracking's configured interval, and its age and reported accuracy satisfy the shared-source policy. The fix passes through the existing scheduled cadence admission, chronological ordering, quality gate, suspect confirmation, and accuracy-refinement pipeline. Shared callbacks do not increase the transmission frequency. An independent fused-location request is registered if the source stops, becomes stale or too slow, lacks permission, reports poor accuracy, or the live-tracking quality gate rejects or suspects the shared fix. Periodic watchdog checks restore fallback if callbacks stop without a lifecycle notification. The bounded refinement request remains independent and keeps its existing limits.

This changes request ownership, not a guaranteed hardware GPS fix count. Validate with recording and guidance starting, stopping, and changing cadence, including screen-off, poor GPS, permission loss, process recovery, and network outages. Compare battery use on the same phone and route before claiming savings.

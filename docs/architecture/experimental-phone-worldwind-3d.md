# Experimental phone WorldWind 3D

The normal phone map remains native MapLibre for online providers and Mapsforge for offline maps. The experimental 3D view uses WorldWindKotlin 2.1.1 as a native Android surface. The 3D surface occupies the map slot inside the existing map screen. It installs the selected local imagery or supported online raster provider, local elevation coverage with optional online fallback, and live visible GPX/location overlays; it never installs a default WorldWind network provider.

Mapsforge decodes the selected OpenAndroMaps `.map` and applies the selected local theme and style/overlays. WorldWind asks for visible Web Mercator tiles; tiles outside map bounds are rejected. Requests for the same map revision, theme configuration, scale, XYZ and resolution share one coroutine job. A single background worker owns Mapsforge rendering; when all waiters cancel, its result is not inserted into the cache. WorldWind receives its own decoded bitmaps and controls their lifetime. WorldWind permanently marks a failed factory image as absent, so the adapter releases that mark after 30 seconds and requests a redraw. This covers failed Mapsforge renders, network errors, undecodable responses and HTTP 408, 425, 429 and 5xx; other HTTP errors such as 404 stay absent until the GL context is recreated. Retries are bound to the view and only reach the network if the tile is still requested.

The per-view LRU retains encoded bytes and charges each entry at least its decoded RGBA pixel size. Its budget is one eighth of the maximum Java heap, bounded between 4 and 64 MiB. This charge is a conservative pixel estimate, not a measurement of WorldWind's transient bitmap, reprojection or GPU allocations. Levels below 16 use 256px imagery; levels 16 and above use 512px only at display density >= 2 and maximum heap >= 256 MiB. The discrete level bands are stable, but level and density are proxies rather than proof of visible improvement; 512px render time, label scaling and memory must be tested on a phone. No disk cache or additional neighbor prefetch is implemented. A future disk cache needs versioned identities for map and all theme resources, bounded eviction, atomic writes and corruption recovery; it would make re-entry faster, but the current cache is released when the view closes. WorldWind already schedules visible imagery and ancestor tiles, so speculative work could delay visible tiles.

The elevation adapter groups each requested grid by HGT tile on a single-lane IO dispatcher and uses the existing three-entry decoded HGT LRU; each group loads its tile once rather than looking it up for every sample. WorldWind controls terrain tessellation and requests coarser or finer elevation matrices as needed. Each grid value is sampled at its cell centre, because WorldWind reads coverage values as cell centres rather than edge points. The matrix pyramid targets 3 arc-seconds when the initial center has standard HGT, and 1 arc-second for detailed HGT, unknown center coverage, or online fallback. Matrix levels are powers of two and may modestly oversample the target. The center-based choice is global to this coverage: a standard center can cap a neighboring detailed HGT tile until the coverage is recreated. Changing the selected DEM source or local terrain data recreates coverage. Online maps may fall back to cached Terrarium data, with at most four source tiles per terrain grid; offline maps do not use network elevation. A grid spanning more than four 1° HGT tiles does not read local HGT: decoding or probing one file per degree made the first coarse grid take 24 s offline and kept online grids that span the globe from ever finishing on a Galaxy S8. Such coarse grids use online elevation when enabled and otherwise stay empty, so distant terrain beyond the finer levels can look flat. The center availability check retries only failed loads and only while the app is resumed. Missing and void samples stay missing, but a grid is rejected when an online tile failed to load or a local tile exhausted memory, so WorldWind retries it instead of keeping holes. A local tile that exhausts memory clears the decoded HGT LRU and is not cached as missing. HGT, gzip and ZIP files remain supported.

WorldWind's public `BasicTessellator.detailControl` remains 12.0; WorldWind chooses mesh LOD. Its texture defaults use bilinear filtering with mipmaps where supported; anisotropic filtering is not exposed by this adapter. A bounded internal exaggeration experiment permits 1.0–1.25 but defaults to 1.0; no device comparison has yet been made. Subtle normal-based Lambert relief uses the protected WorldWind 2.1.1 shadow-layer extension point without scheduling cascaded shadow passes. This relies on 2.1.1 behavior and needs device testing after a WorldWind upgrade. Online imagery receives lighter shading. The initial tilt is 55 degrees from vertical (35 above the horizon), clamped to 60 degrees from vertical to retain the existing 30-degree minimum above the horizon. A ground-clamped camera resolves terrain height once, so it is reapplied when the ground under its target changes by at least 5 m, such as when elevation first loads in the mountains. This is suspended during touch and does not apply to the absolute camera left by a gesture.

An explicit phone debug capture records cache, render, coalescing, cancellation, resolution, HGT load, elevation request and startup counters, plus approximate Java heap and queued jobs. First imagery means first tile rendered, not first visible frame; first GL frame is separate. It also records tile and HGT failures, incomplete grids, tile retries, camera re-anchors, surface start, pause and resume with a rounded camera, and frame statistics. Render time is the main-thread frame preparation; GL time is the draw call on the GL thread, excluding buffer swap and later GPU work, so neither is a GPU frame timing. Gesture gaps measure the time between draws during touch. Failure reasons contain status codes or exception types only, never URLs, because online tile URLs can carry API keys. A capture reveals approximately where it was taken through tile coordinates and the rounded camera. Raster labels remain draped on terrain, while GPX and position remain separate WorldWind geometry layers.

A small terrain progress ring fills as Mapsforge tile renders, online imagery downloads and elevation grids finish, counted against the requests started since the view last had nothing left to load. It stays full until the next request starts a new batch, and a cancelled or failed request still counts as finished. A grid that WorldWind retries later starts a new batch. GPU work is not tracked, so a full ring means the requested data arrived, not that every frame has been drawn.

Offline map imagery has been seen on a phone; terrain, airplane mode, imagery quality, tile seams, lifecycle stress, online providers, and performance still need validation. Large-area elevation sampling, asynchronous tile rendering and duplicate CPU/GPU bitmap allocations can affect startup, memory, frame time and battery. Local elevation errors and absent coverage are currently grouped into a single warning at the initial camera center; subsequent missing tiles are rendered flat. Online raster tiles use the selected provider with attribution and an HTTP disk cache; vector-style providers are not yet supported. The 3D layer stays selected when the base map, theme or online elevation setting changes. The shared map camera preserves center, zoom and bearing when switching back to 2D; 3D tilt is retained when changing the map. The surface restarts from the latest camera and tilt after the map is hidden, and the 3D layer, tilt and camera are restored after activity recreation. Location and track overlays update while the surface remains active, and map search, zoom, orientation and follow controls drive the WorldWind camera. POIs, per-track colors, route editing, comparison rendering, and other 2D map tools are not implemented in 3D. Validate the full offline scenario before using this as a normal map replacement.

# Experimental phone WorldWind 3D

The normal phone map remains native MapLibre for online providers and Mapsforge for offline maps. The experimental 3D view uses WorldWindKotlin 2.1.1 as a native Android surface. The 3D surface occupies the map slot inside the existing map screen. It installs the selected local imagery or supported online raster provider, local elevation coverage with optional online fallback, and live visible GPX/location overlays; it never installs a default WorldWind network provider.

Mapsforge decodes the selected OpenAndroMaps `.map` and applies the selected local theme and style/overlays. WorldWind asks for visible Web Mercator tiles; tiles outside map bounds are rejected. Requests for the same map revision, theme configuration, scale, XYZ and resolution share one coroutine job. A single background worker owns Mapsforge rendering; when all waiters cancel, its result is not inserted into the cache. WorldWind receives its own decoded bitmaps and controls their lifetime. WorldWind permanently marks a failed factory image as absent, so the adapter releases that mark after 30 seconds and requests a redraw. This covers failed Mapsforge renders, network errors, undecodable responses and HTTP 408, 425, 429 and 5xx; other HTTP errors such as 404 stay absent until the GL context is recreated. Retries are bound to the view and only reach the network if the tile is still requested.

Rendered Mapsforge tiles are kept as PNG files in the app cache directory (`worldwind-mapsforge-tiles`), so reopening 3D or returning to an area skips rendering. An earlier in-memory LRU, released when the view closed, recorded zero hits across three Galaxy S8 captures, because WorldWind keeps its own decoded textures while a view is open. Each file name hashes the app version code, which covers bundled theme assets, the map revision (path, file key, size and modification time), the theme, style, overlays and external theme revision, and the scale. A changed input therefore never reuses an old tile, and outdated files age out. Writes go to a unique temporary file and are renamed into place. A file that no longer decodes is deleted and rendered again. The cache removes the least recently used files beyond 128 MiB, trimming to 90%, and Android may clear it. Levels below 16 use 256px imagery; levels 16 and above use 512px only at display density >= 2 and maximum heap >= 256 MiB. The discrete level bands are stable, but level and density are proxies rather than proof of visible improvement; 512px render time, label scaling and memory must be tested on a phone. No neighbor prefetch is implemented: WorldWind already schedules visible imagery and ancestor tiles, so speculative work could delay visible tiles.

The elevation adapter groups each requested grid by HGT tile on a single-lane IO dispatcher and uses the existing three-entry HGT LRU; each group loads its tile once rather than looking it up for every sample. Plain HGT files are memory-mapped, so a grid reads only the pages it samples instead of decoding a whole 1-arc-second file (about 26 MB). Compressed `.hgt.zip` and `.hgt.gz` files, which offline downloads use, are unpacked once into the app cache directory (`phone-dem-unpacked`) and then mapped. Each copy is named after its source's path, size and modification time, so a replaced file unpacks again. The cache keeps the most recently used copies within 256 MB, about ten 1-arc-second tiles, and the OS may clear it. Unpacking runs on its own single-lane dispatcher before a grid enters the elevation lane, so grids whose files are ready keep loading meanwhile instead of queueing behind a multi-second unpack. If unpacking fails, the tile is decoded in memory as before. The same reader serves 2D live elevation and recording, with unchanged sample values. WorldWind controls terrain tessellation and requests coarser or finer elevation matrices as needed. Each grid value is sampled at its cell centre, because WorldWind reads coverage values as cell centres rather than edge points. The matrix pyramid targets 3 arc-seconds when the initial center has standard HGT, and 1 arc-second for detailed HGT, unknown center coverage, or online fallback. Matrix levels are powers of two and may modestly oversample the target. The center-based choice is global to this coverage: a standard center can cap a neighboring detailed HGT tile until the coverage is recreated. Changing the selected DEM source or local terrain data recreates coverage. Online maps may fall back to cached Terrarium data, with at most four source tiles per terrain grid; offline maps do not use network elevation. A grid not fully covered by local HGT files loads its online tiles before joining the elevation lane, so a download of about a second (as measured on a Galaxy S8) no longer holds up every queued grid. The shared online elevation repository loads different tiles in parallel, up to four at once; callers wanting the same tile share one load, and it keeps 32 decoded tiles in memory (about 8 MB). A grid that is only partly covered by local files may download its whole online tile set, at most four tiles, rather than only the tiles covering the gaps. A grid spanning more than four 1° HGT tiles does not read local HGT: decoding or probing one file per degree made the first coarse grid take 24 s offline and kept online grids that span the globe from ever finishing on a Galaxy S8. Such coarse grids use online elevation when enabled and otherwise stay empty, so distant terrain beyond the finer levels can look flat. With online elevation available, a grid whose cells are wider than about 250 m (eight 1-arc-second samples) also uses online elevation instead of local HGT, because a fly-over from a globe view unpacked 25 files (16.8 s) for grids where local detail could not show. Offline maps have no other source and keep reading local HGT up to the four-file limit. If online elevation fails at those scales, the grid is retried rather than filled from local files. The center availability check retries only failed loads and only while the app is resumed. Missing and void samples stay missing, but a grid is rejected when an online tile failed to load or a local tile exhausted memory, so WorldWind retries it instead of keeping holes. A local tile that exhausts memory clears the decoded HGT LRU and is not cached as missing. HGT, gzip and ZIP files remain supported.

The chosen tilt applies up to 50 km away; beyond that its limit shrinks with the logarithm of the distance to straight down at 2,000 km, so a zoomed-out globe sits centred instead of at the bottom of the screen. The chosen tilt is kept and returns when zooming back in, and it is what the 2D map remembers. Zooming out stops when the whole globe fits the narrower screen side with an 8% margin. WorldWind caps the range at twice the distance that fits the globe vertically, which still cropped it across a portrait screen, so beyond that cap the camera, already looking straight down, is raised by the remainder. Each zoom level's first successful online imagery download is logged with its time, to show whether world-scale imagery loads. A ground-clamped camera keeps its height above the terrain under the look-at point. When finer terrain arrives, the camera eases a quarter of the way to the new ground height each frame (about a quarter of a second for a 1,000 m change at 60 fps) instead of jumping, and lands exactly on it. Camera commands and following still place it at once. Each new terrain height is logged once, not on every eased frame. WorldWind's default layers are cleared, so the view adds back only WorldWind's `AtmosphereLayer` sky after the imagery; without it the area above the horizon was black in a tilted view. Its ground scattering pass is skipped (equal fade altitudes would apply it in full), so map colours are not tinted. The sky follows the fixed relief light rather than the time of day. Maps settings > 3D view holds two options, both off by default and applied live without reloading terrain. Elevation colours adds WorldWind's `ElevationHeatmapLayer` at 45% opacity; its blue-to-red scale spans the lowest to highest loaded terrain in view, so the same colour is not a fixed altitude. Relief strength (0-100%) scales the north-west Lambert relief; 50% reproduces the earlier fixed shading of 0.28 for offline maps and 0.12 for online imagery, which already carries natural shading. Before this setting the relief was always on, so the default 3D view is now flatter-looking until relief is raised. WorldWind's public `BasicTessellator.detailControl` remains 12.0; WorldWind chooses mesh LOD. Its texture defaults use bilinear filtering with mipmaps where supported; anisotropic filtering is not exposed by this adapter. A bounded internal exaggeration experiment permits 1.0–1.25 but defaults to 1.0; no device comparison has yet been made. Subtle normal-based Lambert relief uses the protected WorldWind 2.1.1 shadow-layer extension point without scheduling cascaded shadow passes. This relies on 2.1.1 behavior and needs device testing after a WorldWind upgrade. Online imagery receives lighter shading. The initial tilt is 55 degrees from vertical (35 above the horizon), clamped to 60 degrees from vertical to retain the existing 30-degree minimum above the horizon. A ground-clamped camera resolves terrain height once, so it is reapplied when the ground under its target changes by at least 5 m, such as when elevation first loads in the mountains. This is suspended during touch and does not apply to the absolute camera left by a gesture.

An explicit phone debug capture records cache, render, coalescing, cancellation, resolution, HGT load, elevation request and startup counters, plus approximate Java heap and queued jobs. First imagery means first tile rendered, not first visible frame; first GL frame is separate. It also records tile and HGT failures, incomplete grids, tile retries, camera re-anchors, surface start, pause and resume with a rounded camera, and frame statistics. Render time is the main-thread frame preparation; GL time is the draw call on the GL thread, excluding buffer swap and later GPU work, so neither is a GPU frame timing. Move-to-frame time runs from the first finger movement not yet drawn until a frame finishes drawing, and counts as slow above two 60 Hz frames. It replaced a gap between draws during touch, which also counted a resting finger. A movement too small to change the camera can still wait for the next frame and inflate it. A pending movement is cleared when the view pauses, and one waiting more than a second (for example while a panel covered the map) is counted as dropped rather than as a frame time. The summary adds how many movements fell within 16, 33, 50, 100 and 250 ms or above. Online elevation reads log their duration, and a cache-only read that OkHttp answers with a synthetic 504 is logged as `cache_miss` rather than as a failed download. Changes to the 3D relief strength and elevation colours are logged, and their current values appear in the summary. Each compressed elevation file unpacked is recorded with its time. Online elevation preloads are counted with their total time, and a preload taking 200 ms or more, which means it downloaded, is logged with its tile count. Failure reasons contain status codes or exception types only, never URLs, because online tile URLs can carry API keys. A capture reveals approximately where it was taken through tile coordinates and the rounded camera. Raster labels remain draped on terrain, while GPX and position remain separate WorldWind geometry layers.

A small terrain progress ring fills as Mapsforge tile renders, online imagery downloads and elevation grids finish, counted against the requests started since the view last had nothing left to load. It stays full until the next request starts a new batch, and a cancelled or failed request still counts as finished. A grid that WorldWind retries later starts a new batch. GPU work is not tracked, so a full ring means the requested data arrived, not that every frame has been drawn.

Offline map imagery has been seen on a phone; terrain, airplane mode, imagery quality, tile seams, lifecycle stress, online providers, and performance still need validation. Large-area elevation sampling, asynchronous tile rendering and duplicate CPU/GPU bitmap allocations can affect startup, memory, frame time and battery. Local elevation errors and absent coverage are currently grouped into a single warning at the initial camera center; subsequent missing tiles are rendered flat. Online raster tiles use the selected provider with attribution and an HTTP disk cache; vector-style providers are not yet supported. The 3D layer stays selected when the base map, theme or online elevation setting changes. The shared map camera preserves center, zoom and bearing when switching back to 2D; 3D tilt is retained when changing the map. The surface restarts from the latest camera and tilt after the map is hidden, and the 3D layer, tilt and camera are restored after activity recreation. Location and track overlays update while the surface remains active, and map search, zoom, orientation and follow controls drive the WorldWind camera. POIs, per-track colors, route editing, comparison rendering, and other 2D map tools are not implemented in 3D. Validate the full offline scenario before using this as a normal map replacement.
